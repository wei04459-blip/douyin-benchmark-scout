# 接续和验收机制

适用于 workflow_version=3 的新批次。统一入口和主流程见 [批量执行流程](new-workflow.md)。本文件解释程序实际执行的边界，不承诺平台长期免登录或无验证码。

## 一份批次，分阶段留痕

批次目录是唯一权威状态。batch.json 保存范围与逐页搜索观察；竞品库.json 保存候选、固定入选和初读；指标任务.json 与材料队列.json 保存各自尝试。接续任务.json 是根据这些台账重新计算的待办，不能反过来声明完成。没有引入第二份数据库状态。

台账使用临时文件、写盘和原子替换。读改写事务加进程锁；材料、指标与搜索各有运行锁，进程退出自动释放。保存下载证据先于转录，来源先于搜索完成观察。中断遗留的 preparing/running 会记为 interrupted，已校验视频和转录片段继续复用，旧版本与失败原因保留。

## 代理如何接续

1. `start.py next` 输出搜索、指标、入选、材料、分析和导出待办。返回码2表示仍有工作，不能理解成“程序坏了”或自动终止整个代理任务。
2. `start.py resume` 补公开指标，准备已入选材料，并对暂时性错误最多执行3轮、2/4秒退避。每项累计普通尝试最多3次，重复调用不会重置。已完成项跳过。
3. 若当前采用Kimi且会话已经核实，resume加 `--session` 可执行未完成关键词的一次有界搜索；没有session不创建或控制浏览器。Computer Use由代理逐页操作独立研究窗口，再交给 search_checkpoint.py 保存。退出一词后，继续其他可独立处理的词。
4. 代理完成相关性选择、全文初读、关键画面查看与Excel视觉检查，再运行 next。清单未空时继续工作，除真实访问阻碍或缺少必要用户信息，不让用户逐阶段催“继续”。

脚本不代替模型读取视频内容；resume不会自动选择作品、编写分析、批准视觉检查或生成完成回执。

## 搜索接入

search_checkpoint.py 接收真实观察与来源项，自动合并同ID作品并计算进度。默认延续尚未结束的同次尝试；明确重启查询才加 `--new-attempt`。同一尝试多页观察只算一次尝试。不得在超时后伪填 target_reached 或删除失败观察。

新批每词默认40个去重作品。首屏+最多12次滚动、180秒、连续3次无新增构成停止边界；适配器请求亦有超时。达到边界不自动证明结果已尽。只有达到本词目标、对应结果区有明确结束证据、或原词首次确认空结果才通过范围验收。前面已见作品、后来变为空页时记录矛盾，保留作品并待核实。

page_loaded/query_confirmed/cards/evidence_text仍需真实工具观察支撑；程序只能核对提交记录内部一致，不能证明代理没有伪造原始观察。代理禁止根据标题猜ID、补不存在的页面文字或模拟成功响应。

## 错误与恢复

| 类别 | 自动处理 | 接续条件 |
|---|---|---|
| 网络、超时、识别进程暂时退出 | 退避后重试失败步骤 | 累计普通尝试不足3次 |
| 登录、滑块或访问限制 | 停止受限网络通道，本地材料可继续 | 真实核对恢复后传 --access-restored，保留恢复记录 |
| 来源过期、作品身份不符 | 保留原记录，不换作品凑完成 | 重新核实同作品来源后 --retry-failed |
| 本地运行环境或模型缺失 | 保留队列 | 修复路径/依赖后 --retry-failed |
| 空片段、时长不符、材料变化 | 保留视频、已有片段和问题 | 补失败片段或看画面并接入核实文字 |

转录按120秒切片。缓存键包含媒体、模型文件哈希、识别引擎版本和关键参数；只复用正文/分段一致、时间有效的成功片段。某片段为空也保留为未完成，即使是无声段，仍由代理核对画面并记录，不能自动当成完整口播。

## 完成与旧批兼容

最新搜索尝试、每项当前资格、完整材料、逐条初读与导出回执都通过才完成。未入选候选也会显示在Excel里，因此它们同样纳入输入指纹。文件存在、HTTP 200、模型退出码或报表成功保存均不能单独使整批完成。

旧批未冻结 search_policy 时保留其旧范围口径，不冒称当时已经每词抓了40条。最新尝试、材料核实与当前资格规则仍适用。新指纹版本会使旧完成回执在重新验收时需要重新导出/复核，不改写原Excel或旧分析。验证旧数据时优先使用副本。

维护后运行 `scripts/self_test.py`（Python需有openpyxl用于旧表读取回归），再做本地真实转录和新/旧批次导出检查。单元测试和历史副本通过只证明这些场景，新一轮线上批量成功率仍需实际采集验证。
