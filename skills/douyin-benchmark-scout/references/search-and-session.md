# 检索与下载通道

## 搜索

1. 选择当前可用的Computer Use或Kimi独立研究页。Kimi是可选适配器，需已经建立可用会话；不要求用户关闭或切换已有工作标签。
2. Computer Use逐页观察后，用 `search_checkpoint.py` 保存真实观察与来源项，结构见 [批量执行流程](new-workflow.md)。
3. 已打开Kimi独立研究页时，可用 `collect_visible_search.py --root <批次> --session <本轮会话> <关键词...>` 保存可见卡片及同页公开响应。脚本不创建窗口，也不获取登录信息。
4. 仅读取当前页面已观察到的响应，用可见标题核对作品ID，保存需要的公开字段。不要保存请求头、含登录令牌的请求地址或无关浏览内容。粉丝缺失时留空。
5. 保存每页新增，按范围和停止原因判断是否搜完。明确空结果与页面未加载、正文过期、响应未匹配是不同状态。

## 作品材料

固定入选后交给材料队列。已有公开媒体地址可以验证下载，否则调用已安装的Douyin_TikTok_Download_API解析同一作品。下载、转录与初读分别记录。安装目录、运行环境和返回数据必须实际核实，安装成功不等于线上通道可用。

HTTP 200空正文表示获取失败，不能据此断言作品不存在或必然登录过期。保存断点并检查正常页面访问、既有运行环境和上游兼容性。不自动读取或导出浏览器凭据；任何用户明确授权的本地配置处理均应保持凭据在既有客户端内，不写入对话、研究报告或GitHub。

验证码或访问限制出现时停止受限通道；正常恢复后接续同一批次，不换通道规避。

## 内容边界

机器稿中的专名、数字和工具名称可能有误。保留原稿与核实版本，结合字幕和关键画面分析。收入、效果和促销信息保留为作者主张，转录成功不使其变成事实。

历史材料回归只能验证兼容性，不能计入本次新视频采集量。当前通道是否可用、用了什么搜索范围、实际完成多少条，以本批真实观察与验收为准。
