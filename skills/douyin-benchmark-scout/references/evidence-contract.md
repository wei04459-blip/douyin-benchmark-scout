# 材料验收与人工语义审核

`scripts/verify_evidence.py` 是独立只读检查器。输出写到不存在的新文件；不会修改输入、状态或原视频。

```bash
python scripts/verify_evidence.py --manifest <运行目录/待分析数据.json> --analysis <分析.json> --output <新诊断.json>
```

退出码 0：技术检查通过且提供了绑定材料指纹的审核记录。退出码 2：材料不足或未审核。`--skip-media` 仅供快速诊断，永远不能通过正式验收。FFmpeg 按单线程完整解码音视频，每条有超时；超时仅表示未验证。

## 分工与局限

程序验证文件存在、完整解码、转录非空、材料 SHA-256、引用原文和分段时间对应。程序不能证明转录准确、画面属于该作品、观点解释正确或审核者真的看过材料。代理必须实际核对，再填写审核记录，禁止为了通过检查机械补上 true。

本文件描述旧精读路线的口播验收。批量初读路线已支持通过 `adopt_reviewed_text.py` 接入实际核对的画面或混合文字，详见 new-workflow.md；未核对的无口播作品继续留在候选或待核验队列，不能用标题补出分析再标完成。已删除媒体的历史条目只能诊断为现在无法追溯，不得倒推其历史下载失败。

## 分析记录

保留原有分析字段，逐条增加 `evidence_review`：

```json
{
  "reviewer": "实际执行审核的代理或用户",
  "reviewed_at": "2026-09-07T12:00:00+08:00",
  "media_sha256": "审核所用视频的完整 SHA-256",
  "transcript_sha256": "审核所用 TXT 的完整 SHA-256",
  "transcript_checked": true,
  "identity_checked": true,
  "full_content_checked": true,
  "claims_checked": true,
  "quality_notes": "具体记录核对的方法、识别错误、事实边界和未解决限制",
  "references": [
    {"field": "hook", "quote": "转录中的连续原话", "start": 0.0, "end": 4.8}
  ]
}
```

上述对象放在 `items[作品ID].evidence_review`。hook、structure、emotion、summary、viral、migration 都需要可定位引用；一段可支持多个字段，但应解释各字段与证据的关系。start/end 单位为秒，范围须包含引用对应的完整转录分段。TXT 旁须有同名 JSON，含 segments[{start,end,text}]。引用应跨越真实内容的关键部分，不能用同一句开头冒充全文分析。

审核范围必须明示：逐字听校，或语音转录加来源字幕交叉核对。后者只确认文本足以支撑内容分析，不宣称逐字听校。使用后一条路径时，保存全片字幕观察与纠错记录；字幕是作者呈现的文字，也可能与语音不同，冲突不能自动任选一份。特别核对标题主题、开头、结尾、工具名、数字、关键论点和明显不通顺的句子；发现系统性错误应重新转录或逐段校对。短口播仅提示，不用固定字数判定失败。身份核对要确认原网页标题/账号/作品 ID 与视频素材一致，不能只根据文件名。

传播解释必须写作假设并说明其他可能原因；收入和效果是视频作者主张，不自动成为事实。迁移建议区分用户已确认经历与建议，不编造个人实践。

## 正式出表

工作簿生成器自身执行验收，直接调用生成器也不能绕开。未通过时，不生成正式新表、不推进游标、不写 processed。部分失败先交付诊断与候选清单，补齐后重试；不要自动缩减 manifest 来掩盖缺项。

正式出表成功后分别写 research_status、export_status、media_retention。保留媒体，旧配置中的自动删除开关不再生效。后续需要清理时另建明确的清理流程，不复用研究完成标记。

原有工作簿可能含未经核验的历史行，它们不因本次导出而自动通过验收。报告本批审核数时以 manifest 为准，工作簿总行数只表示累计收录数。
